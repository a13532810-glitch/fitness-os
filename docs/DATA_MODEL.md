# 数据模型与迁移

IndexedDB 数据库 `fitness-os-real` 和 `fitness-os-demo` 物理分离，Dexie schema version 1。localStorage 只存可丢弃的空间偏好，实际训练全部在 IndexedDB；不自动同步。所有实体有稳定 `id`、ISO `createdAt` / `updatedAt`。用户新实体通过 `crypto.randomUUID()` 生成；内置动作/计划的固定 ID 只作为稳定引用，不表示训练成绩。

| 表              | 内容和关联                                                                                           |
| --------------- | ---------------------------------------------------------------------------------------------------- |
| exercises       | 动作名称、肌群、默认器械、动作方式、启用状态                                                         |
| workoutPlans    | A/B/C 各一份，可暂停轮换；items 引用 exerciseId，保存目标组数与次数范围                              |
| workoutSessions | 日期、本次类型、草稿/完成/未完成、时长、疲劳、感受、动作项快照                                       |
| workoutSets     | sessionId + itemId + exerciseId 引用本次快照；order、实际重量、次数；同一动作可不同重量              |
| bodyMetrics     | 日期、可空体重kg/腰围cm、测量备注；至少一项有效                                                      |
| trainingGoals   | 动作/器械/方式、重量、组数、次数范围、依据、来源、待确认/已确认/归档                                 |
| weeklyReports   | 对应日期与手动保存的文本结论，不执行其中的指令                                                       |
| settings        | 唯一 preferences；90天开始日期、可选周期次数目标、本周计划次数、主题、备份生成时间和人工恢复测试勾选 |

训练动作快照有独立 itemId，保存当时名称、器械、方式、目标组数/次数范围和质量/余力确认。改计划或默认动作不会重写快照。重量目标存 goals，与实际组严格分开；目标重量不会自动填入实际成绩。空白组用 null，0kg 是允许的实际重量，不能用0冒充缺失。删除训练与关联组在同一事务完成。

训练保存通过事务写日志并替换该训练的所有组，避免部分写入。编辑器串行执行自动保存队列；失败保留当前编辑内容并提示，最后成功前不能通过弹窗关闭离开。预览恢复期间若任何标签页改动数据，恢复拒绝并要求重新预览。

## 备份版本

外层 `{format:'fitness-os-backup', version:1, mode:'real', exportedAt, data}`。完整包含以上八表，导出不含演示库。严格 Zod 校验实体、数值、日期、字段、大小；关联校验涵盖唯一ID、三类计划、动作引用、训练/动作项/组引用、唯一组顺序、时间顺序和目标引用。确认状态的目标必须有器械与方式。超过20MB的文件在UI读取前拒绝。

合并使用表内稳定ID，新ID补充，同ID不覆盖；冲突计数在预览中显示。若合并结果关联不完整则拒绝，不试图猜测重命名关系。覆盖导入须明确输入确认语句。写入在同一事务内，核对所有表数量，异常回滚。

## 后续迁移规则

1. 增加持久化结构或索引时新增 Dexie `version(n).stores(...).upgrade(...)`，不得删除数据库重建。
2. 备份破坏性格式改变时提升外层 version，先识别版本并在内存中迁移、校验、预览，再事务写入。当前仅接受版本1，未来版本会明确拒绝。
3. 新增可选字段需兼容旧备份；当前 cycleTargetSessions 可缺省。未知字段拒绝，以免静默丢弃新版本内容。
4. 迁移前导出备份；测试旧库升级、失败回滚、离线重开、关联数量。Service Worker 缓存升级独立于 IndexedDB schema，不清库。

## 分析口径

自然周从周一开始，仅已完成训练计次数。草稿排除趋势；未完成实际组计总次数/训练量，但不冒充完成训练。力量比较要求同动作、同机器、同方式、同目标组数且有效组齐全；目前自动结论只比较所有组相同重量时的总次数。混合重量呈现逐组事实，不自动换算最大力量。最高组重量图只展示原始重量，不单独判定进步。至少3次可比记录才提示持平或连续下降。体重/腰围少于2点显示不足；不预测肌肉增长。

## V1.1 兼容约束

保留全部8表、字段、ID、数据库名、version 1 和 JSON version 1。不增加云存储，不执行迁移或初始化清库。训练页折叠状态、输入中间文本、完成总结、分页与趋势时间范围属于 UI 状态。

器械记忆从最近「有有效实际组的已完成训练」的动作快照读取，不使用未完成动作或草稿作为默认设置。如果用户在该训练之后主动修改动作默认配置，则尊重该修改。配置记忆不会复制完成次数、修改历史快照或覆盖已确认目标。

没有有效组的动作不作为上次实际成绩或力量比较点；原数据库记录保持原样。长历史读取按 sessionId/itemId 建索引，仍逐组保留原重量、次数与顺序。
