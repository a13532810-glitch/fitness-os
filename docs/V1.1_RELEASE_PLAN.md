# V1.1 发布与回滚准备

本轮只提交 `feature/fitness-os-v1.1-mobile-ux`，不合并或部署。线上 V1.0 源码基线：`805e67f7191d305fb4c1b9bbbad8c8b8351e5a51`。

## 确认后才执行的发布步骤

1. 用户审阅截图、候选版本及数据兼容报告，并完成真实 iPhone Safari / 主屏幕 PWA 验收。
2. 从原使用入口导出完整 JSON，确认文件实际保存，并完成安全的恢复测试。不要清网站数据。
3. 复核依赖审计、开发分支提交和差异，确认不含备份、健康记录、私钥、证书或本机目录。
4. 单独获得发布确认后，才合并到 main，触发 Pages。保持原 HTTPS origin、`/fitness-os/`、manifest id/scope、数据库名不变。
5. 用户先保存草稿，再接受 SW 更新。按记录数、组数、逐组实际和目标复核；飞行模式冷开、编辑后再联网核对。

## 回滚

旧数据库和 JSON 结构完全保留，不能通过删除 IndexedDB 或清网站数据回滚。已在隔离 Chromium / WebKit 中执行真实 V1.0 构建 → V1.1 → V1.0 的 SW 更替，逐字段核对原有已完成训练及部分填写草稿。

若发布后出现问题，先停止进一步发布，保留并导出当前数据；经确认后用恢复 V1.0 代码的提交重新部署。只回滚静态代码，不删库、不导入旧备份覆盖新增记录、不改 stable IDs。本轮未执行生产回滚。

开发检查工作流无 pages:write；Pages 的 build/deploy 两个 job 都要求 `github.ref == 'refs/heads/main'`，防止从开发分支手动触发生产部署。

## 环境限制

localhost 为本机可信测试上下文，可自动化验证 SW。iPhone 不能访问 Mac 的 127.0.0.1；普通局域网 HTTP 不能完整验证 SW/PWA 离线。若需发布前在真实 iPhone 测候选版，应另行准备手机信任的局域网 HTTPS（私钥只留本机），或经用户确认的独立预览环境。本轮没有新建公开预览。
