## 修改摘要

- 全站统一浅米白、深绿、细分隔线、克制圆角、数字等宽和可见焦点；减少动态效果偏好继续生效，保留深色和桌面布局。
- 总览每个动作单行显示名称与目标，展开才显示肌群、器械、上次成绩与已确认目标。保留数据入口，无嵌套目标卡片。
- 计划默认显示整套动作结构，点击动作才编辑三列组数/次数，计划名点按编辑；A/B/C、自动轮换、增删动作与动作库保持。原版无排序能力，本轮不增加拖拽。计划保存改为文档流，避免覆盖最后字段。
- 趋势三个指标在同一区域，统计口径移入帮助；每周真实图表靠前，空状态精简。器械/方式两列，默认仍取最近有效记录，严格按条件比较；最高重量不直接判定进步。
- 身体变化顶部独立展示最新体重、腰围与测量日，分别判断趋势点数。0–1 点仅短提示，至少两点展示各自真实曲线。保留编辑、删除确认和原精度。
- 训练历史优先展示已完成训练，保留未完成训练；有效草稿集中到继续训练；无时长不显示“未填分钟”。新增空白草稿本机审计预览和安全清理。
- 下次目标默认只显示动作、可选重量、组数、次数范围；来源、器械、方式、依据在高级选项，缺少必要信息时提示并展开；仍保存为待确认、仍需人工确认，不改实际成绩。
- AI 页面按概况、导出、手动保存、档案排列；JSON 为主操作，Markdown/复制提示词保留，输入框默认三行并随输入扩展，档案可编辑原记录。没有付费 AI API、自动分析或建议自动转目标。
- 弹窗监听可视视口高度、保留滚动、44px 关闭触控范围、安全区和精致可见焦点；训练沿用完整键盘适配。修复桌面更多工具栏拦截计划按钮，以及趋势周图卡片撑宽移动视口的问题。

## 草稿根因、复现与修复

[原版隔离复现证据](v1.2.1/baseline-draft-reproduction.json)：从 Git d4c980d 在临时目录独立构建，390px 隔离 Chromium 连续打开关闭训练十次，产生 **10 份 draft、0 个填写组**；保存了合成草稿的 ID、创建/更新时间和状态。没有访问用户个人浏览器或真实训练库。

根因有两个明确路径：Workspace.start 创建内存训练后立即调用 saveSession，尚未输入即写入 IndexedDB；WorkoutEditor.change 无条件保存，切换训练类型、载入默认空白组也会持久化。

修复后 start 只建立内存实例。保存门槛排除打开、浏览、默认组、类型切换等行为；首次实际重量（含 0kg）、次数、时长或主动器械编辑才自动保存；后续串行事务沿用同一 ID。已有记录即使清空成绩也保存原 ID，不擅自删除。关闭等待队列；放弃新训练修改会撤销本次新增草稿，旧训练则恢复初始快照。

保守内容判断保护半填组、备注、疲劳、时长、quality/reserve 和器械/动作方式注记。空白旧草稿不再混入历史，但不自动删除。用户在“检查空白草稿”展开预览，核对创建/更新时间，下载完整 JSON，并明确确认后清理。清理事务重新读取每条记录与关联组；预览后新增内容的记录会跳过；完成记录不能清理。不按同一天或同一类型去重，不合并不同训练。

新训练的“放弃修改”使用打开时固定的存在性快照，而非会随自动保存刷新的数据列表，避免撤销操作重新保存初始空白记录。

用户真实 iPhone 中已有草稿的数量和具体内容尚未读取；本机应用预览提供审计入口，不能将隔离合成记录冒充真实数据审计。器械/方式非空的旧草稿即使没有成绩也保留，宁可少清理。

## 数据兼容性

数据库名 fitness-os-real、Dexie schema 1、八张表和备份 version 1 保持。无需迁移或降级。src/model.ts、src/analytics.ts、src/backup.ts 与基线逐字不变；src/db.ts 仅新增内容判断与受保护清理，原 schema、saveSession、删除训练事务、配置记忆与默认计划不变。

保留历史隐藏字段、实际重量/次数、目标状态、身体指标和周报。旧版备份解析、合并/覆盖预览和原始导出契约继续接受验证；升级和回滚不清网站数据。代码回滚到 d4c980d 即可读取相同数据，主动清理的空白记录可用清理前备份合并恢复。

全部自动化使用隔离、临时、明确虚构数据；没有上传健康数据或浏览器配置。
